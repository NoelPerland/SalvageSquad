# Focused steering, health, audio and boss playtest

Use existing authored shifts and art. Do not rerun PresentationUpgrade or PlayFeelTuning. Use pinned Unity version and development/test commands in project AGENTS.md.

## Record each run

Record build commit, device, resolution, input method, shift and route. Ask an unfamiliar player to start without coaching. Record time until they demonstrate steering and describe health/damage; record mistakes at gate rows, result, boss armor-open time, boss-death time, survivors and chosen upgrades. Ask whether they want another run before suggesting one.

For audio, listen on actual speakers/headphones at comfortable volume. Note overlapping cues, audible clipping, masked danger warnings and uncomfortable repeated sounds. Numeric peak measurements cannot replace listening.

## Acceptance and tuning

Existing small-sample design targets: 8/10 understand controls within ten seconds; 6/10 voluntarily replay. These are targets, not current results or retention estimates. Record actual sample size and observations.

Compare weak/novice and strong builds. If strong builds end boss phase before its attacks are readable, adjust one existing boss parameter at a time, rerun weak and strong routes and retain only measured improvements. Do not infer enjoyment from automated victories. Do not change economy or reward promises to satisfy a test.

After each change run existing EditMode/PlayMode coverage, visible win/loss/retry, pause, reset/pool checks and Windows rendering measurements. Physical-phone safe areas, touch comfort, frame stability, audio and iOS signing remain separate release checks.
